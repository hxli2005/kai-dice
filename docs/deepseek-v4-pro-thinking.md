# 我给 DeepSeek 传了个上限，它当没看见

### ——V4-Pro 正式版「默认思考」实测

> 测试时间：2026-08-14。模型：`deepseek-v4-pro`（官方端，即 V4-Pro-0813 正式版）。

## 省流版

- **默认开启思考。** 什么参数都不传，一次大话骰决策就烧掉 3072 个输出 token——**全是推理，正文 0 字**。
- **OpenAI 给的解药，它不吃。** 我传入 `max_completion_tokens: 3072`，它返回 HTTP 200，随后生成了 **15809** 个 token，跑了 **222 秒**。不是报错，而是**当没看见**。
- **瞎编的参数也照收不误。** 我传入一个纯属捏造的 `totally_bogus_param: true`，照样收到 HTTP 200。**这个 API 会静默吞掉未知参数**——所以「我设了上限」这件事根本无法验证，你只能从账单上发现真相。
- **同一道题，关掉思考只需 2 秒、95 个 token**；开着思考则要 65 秒、4500 个 token，**答案长度却几乎一样**。
- **每个可用答案的成本**：关思考为 ¥0.0105；开思考、给 8192 预算时为 **¥0.175（16.7 倍）**；给 3072 预算时则是**无穷大**——0/3 可用，钱照付。
- **质量呢？** 和 OpenRouter 上的老量化版相比，在一项几乎没有解释空间的硬指标上，**看不出任何改善**（1/71 vs 2/22，差异不显著，且样本量较小）。
- **可以关闭思考**：`reasoning_effort: "none"` 和 `thinking: {type: "disabled"}` 有效；`enable_thinking: false` 无效——而且 API 不会告诉你。

## 我为什么会去测这个

我在做一个叫**《开！》**的单机大话骰游戏：对面不是脚本，而是一个接入大语言模型的对手。它跟你使用同一套引擎接口、看到同样的信息，开牌前会先亮出自己的想法，还能跨局记住你的打法。模型可以更换——换一个型号，就等于换了一个对手。

所以，我得知道每个型号每次决策要花多少钱、等多久。**这不是评测机构的好奇心，而是被账单和延迟逼出来的活。**

然后，我撞上了这堵墙。

## 第一次撞墙：付了钱，拿回一个空字符串

一手大话骰决策的提示词约 3200 字。给 `max_tokens: 3072`，连续三次调用全灭：

```
finish=length  完成tok=3071  其中推理=3071  正文=0字  50s
finish=length  完成tok=3072  其中推理=3072  正文=0字  47s
finish=length  完成tok=3072  其中推理=3072  正文=0字  42s
⇒ 可用 0/3
```

**三千多个输出 token 全部花在推理上，正文一个字都没轮上。** 计费按实际生成量计算，所以这三次调用的钱一分不少地付了，我却只拿回三个空字符串。

更要命的是，它在系统里呈现出来的结果是这样的：模型没有返回可解析的动作 → 我的兜底逻辑判定「这一手不合规」→ 统计表上出现一行 **「这个模型 94.4% 的手不听话」**。（这个数字来自本项目 08-13 批次的记录，并非本次实测。）**我差点就把一个真实存在的预算问题，记成了模型的品行问题。**

## 那到底要给多少？

同一道题，四种配置各跑三次：

| 配置 | 可用 | 完成 tok | 其中推理 | 正文 | 耗时 |
|---|---|---|---|---|---|
| 思考开 · `max_tokens`=3072 | **0/3** | 3071–3072 | 100% | **0 字** | 42–50s |
| 思考开 · 8192 | **1/3** | 7837–8192 | ~95% | 0／118 字 | 121–126s |
| 思考开 · 32768 | 3/3 | 3220–5785 | ~97% | 117–140 字 | 49–82s |
| **思考关** · 3072 | **3/3** | **84–107** | — | 123–156 字 | **2–4s** |

三件事同时成立：

**① 预算给得越紧，模型就越容易贴着上限烧完。** 3072 的预算烧到 3072，8192 的预算也基本烧到 8192。只有把预算抬到 32768（远高于它实际需要的 3200–5800），它才能稳定地自然停止。

**② 推理量难以预算。** 同一道题，推理 token 在 **3137–5691** 之间波动；不设上限时甚至飙到 **15774**。这已经不只是「想得多」，而是**你根本没法为它做预算**——波动接近一倍，到底该按哪个数配置？

**③ 想了那么久，答案却没有变长。** 关思考时，正文为 123–156 字；开思考时，则为 117–140 字。**多花的 47 倍 token 和 22 倍时间，并没有换来更长或更完整的答案。**

对我这种应用来说，还有一个更致命的问题：**单局节奏预算只有 30–60 秒**，而思考档下一次决策就要 49–222 秒。**这已经不是贵不贵的问题，而是产品根本无法成立。**

## 这是协议的锅，还是 DeepSeek 的锅？

发文前，我把这个问题单独测了一遍。答案是：**两边都有，但不是五五开。**

**协议那半边**（OpenAI 兼容协议固有的问题）：`max_tokens` 把推理和正文塞进同一个预算，一旦推理耗尽额度，正文就只能空手而归。OpenAI 自家的推理模型也有这个坑——正因如此，它才新增了 `max_completion_tokens`，并在文档中明确警告「预算太小可能得到空回复」。**这一半，怪协议设计。**

至于 **DeepSeek 那半边**，我把相关参数逐个测了一遍：

| 我传的 | 本该发生 | **实际发生** |
|---|---|---|
| 什么都不传 | — | **默认开思考**，烧光预算 |
| `max_completion_tokens: 3072` | OpenAI 的标准解药 | **静默忽略**：生成 15809 tok、耗时 222 秒 |
| `reasoning: {max_tokens: 1024}` | OpenRouter 的解法 | **静默忽略** |
| `reasoning_effort: "none"` | 关思考 | ✅ 生效（18 tok，1 秒） |
| `thinking: {type: "disabled"}` | 关思考 | ✅ 生效（18 tok，1 秒） |
| `enable_thinking: false` | 关思考 | **静默忽略** |
| `chat_template_kwargs: {…}` | 关思考 | **静默忽略** |
| `totally_bogus_param: true`（我瞎编的） | 应当报错 | **HTTP 200，静默吞掉** |

最后一行，正是所有问题的根源。**这个 API 会静默接受未知参数**，于是上面每一个「静默忽略」，看起来都和「设置成功」一模一样。你传了上限，收到 200，以为已经限住了——**直到账单告诉你：并没有。**

其中最刺眼的是 `max_completion_tokens`：这是 OpenAI 专门为推理模型设计的参数，解决的恰恰就是本文所说的问题。DeepSeek 收下它、返回 200，然后放任模型生成 15809 个 token。**不支持，完全可以报错；静默忽略，却是最坏的一种处理。**

所以我的结论是：**协议挖了坑，DeepSeek 把坑挖深了，还撤走了梯子。**

## 那正式版至少更强吧？

这是我最想替它说句话的地方，可惜数据并不配合。

先说价格——**这里有个很容易被误解的地方**。OpenRouter 上老版 `deepseek-v4-pro` 的标价为每百万 token $1.17/$2.34，正式版 `-0813` 为 $0.43/$0.87，官方端则为 ¥3/¥6（约合 $0.42/$0.85）。**看起来，正式版的价格降了约三分之二。** 但 OpenRouter 对老部署原本就定价偏高，其中有多少来自渠道加价、多少来自模型降价，我无法区分。**所以，「正式版涨价了」这句话，我不能说。**

**真正上涨的是「每个可用答案」的成本**：关思考时，每手 ¥0.0105；开思考、给 8192 预算时，三次调用中只有一次可用，算上另外两次的浪费，就是**每手 ¥0.175，达到前者的 16.7 倍**；给 3072 预算时则是无穷大——一次都用不了，钱却照付。**无论标价降不降，最终都会被这个乘数吃掉。**

质量方面，我选了一项**几乎没有解释空间**的硬指标来比较两个版本：当牌桌上出现「这口报价仅凭模型自己手里的骰子就已经成立」的局面时，它却仍然选择开牌——**这是必输的，没有任何策略上的解释空间。**

| 版本 | 该局面手数 | 误开 | 误开率 |
|---|---|---|---|
| 老版（OpenRouter 量化） | 71 | 1 | **1%** |
| 正式版 0813（官方端） | 22 | 2 | **9%** |

**z=1.22，差异不显著。** 所以，严谨的说法不是「正式版更差」，而是：**在这项指标上看不出任何改善；如果确实存在差别，方向反而是变差。**

⚠️ 这项结果需要打折看待：两个版本**从未在同一批次中对打过**，跨批比较混入了不同对手、不同种子和不同提示词版本的影响；正式版也只有 22 个此类局面，样本量较小。**这些数据只够证伪「明显变强」，还不足以证明「变弱」。**

## 结论

我并不是在说「DeepSeek 不行」。V4-Pro 关掉思考后，2 秒就能给出一个干净的决策，每手只要一分钱，在我的牌桌上表现得相当好——**我的托管席现在用的依然是 DeepSeek。**

真正的问题，是三个产品决定叠在了一起：

1. **默认开启思考**——对于按次调用的应用，这是净负担，而不是赠品；
2. **不提供可用的推理预算上限**——OpenAI 和 OpenRouter 的写法都会被忽略；
3. **静默吞掉未知参数**——于是前两个问题**变得难以诊断**。

第三点才是最该改的。**一个会报错的 API，用户十分钟就能查明问题；一个静默返回 200 的 API，却会让用户从账单和一张「94.4% 不听话」的假统计表开始，倒推问题到底出在哪里。**

如果你也在按次调用它：**记得显式传入 `reasoning_effort: "none"`**（或 `thinking: {type: "disabled"}`）。不要用 `enable_thinking: false`——它没用，而且 API 不会告诉你。
