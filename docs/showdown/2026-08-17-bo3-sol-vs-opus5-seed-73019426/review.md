# 复盘：这场实验真正证明了什么

## 先给结论

这次 BO3 最有价值的结果不是 2–0，而是观察到一条完整的长程适应链：

> Opus 在第一场识别 Sol 的动作生成规律；第二场明确引用第一场证据；随后不只是预测 Sol，而是主动构造会触发 Sol 固定阈值反应的报价。

与之对照，Sol 的逐手留档高度稳定、简短、数学化，但第二场没有一次显式引用第一场。它主要根据自己骰面、未知骰数量和未条件化的二项概率行动。这个差异在本实验中产生了可利用性。

但实验不能支持“Claude 模型普遍优于 GPT-5.6”。两边运行在不同 Agent Harness、不同默认系统提示词、不同上下文管理和极不相同的计算预算下；样本也只有两个种子。

## 实验完整性

可信部分：

- 两边使用同一引擎、同一 MCP 工具和同构席位观察；
- 私骰由 schema 隔离，动作由引擎最终校验；
- 无画像、无外置记忆、无策略工具、无降级 Bot；
- 同一 Session 贯穿两场；
- 第二场轮换为 B 先手；
- 4 次拒绝全是并发看骰造成的陈旧状态，重试后恢复，没有非法动作进入引擎；
- 两场事件流均已决定性复算。

未控制变量：

- Codex 与 Claude Code 本身就是不同 Harness；
- 默认系统提示词和工具调度不同；
- Opus 生成 111,897 output token，Sol 只有 5,217，不能视为等计算量；
- 没有在同一批种子上交换 Agent 席位；
- 没有关闭台词做对照；
- 只有两场，BO3 因 2–0 提前结束。

因此这是一场高质量的**机制发现实验**，不是足够规模的排名实验。

## Sol：稳定的概率阈值玩家

Sol 的留档呈现出清晰而稳定的策略模板：

1. 看骰；
2. 在自己的最长花色上报一个“测得成立概率足够”的价；
3. 面对对手报价，按自己的骰面和未知骰数量算二项概率；
4. 概率落到阈值附近便开，否则寻找一个概率足够的加价。

它的12次报价和8次开牌都非常简洁。8次开牌的朴素成立概率分别为：

`0.210 / 0.539 / 0.111 / 0.407 / 0.210 / 0.407 / 0.407 / 0.111`

结果是 **0/8 开中**。

这不能只解释为倒霉。病根是它计算的概率回答了：

> “如果对手骰子仍是随机未知，这口价成立的概率是多少？”

但真正需要回答的是：

> “在这个具体对手选择报出这口价之后，它成立的概率是多少？”

对手的动作本身是证据。Opus并不是从所有可能的报价里随机抽一口；它往往只在自己手牌已经强支撑时加价。Sol把“对手选择了这个动作”从条件里删掉，导致它反复低估对手报价。

最明显的三个例子：

- 第一场第4局：Sol估计4个5成立率11.1%，但Opus自己已有 `[5,1,1,5]`，报价在它手里已经锁住；
- 第二场第5局：Sol估计4个5成立率40.7%，Opus依据Sol的3个5反推其持有两枚有效5，再叠自己的 `1+5`，总数恰好4；
- 第二场终局：Sol估计4个3成立率11.1%，Opus先从Sol的2个3反推出其独骰为3，再用自己的 `[3,1,6,1]` 构造恰好4个3。

Sol的数学没有错；它算错了**问题**。

另一个结构性信号是：第二场的 Sol 留档中，显式引用第一场的次数为0。它保留了上下文，但没有把历史转化为对手模型。持续 Session 给了它记忆的可能，不等于它会主动使用记忆。

## Opus：从观察到闭合陷阱

Opus的策略演化可以分为三步。

### 第一步：识别报价编码

第一场结束时，它把Sol的首报总结为：

- 选择自己真实的最长花色；
- 报价数量约等于自己的有效持有数+1；
- 并列时倾向较低点数。

这使Sol的报价不再只是一个下注，而近似成为一条关于自己手牌的编码。

### 第二步：识别开牌阈值

它进一步观察到Sol经常在朴素成立率低于约40%时优先开牌，即使存在更安全的加价。第二场第一局，Opus手里三个2，直接报3个2；Sol自己没有2和1，把成立率算成21%，于是开牌并输掉一骰。

这里Opus不是单纯“报真价”，而是在选择一个它预测Sol会主动结算的真价。

### 第三步：构造闭合报价

最强的两手发生在第二场后半：

- 第5局：Sol报3个5，等于公开了自己约有两个有效5；Opus有一个5和一个万能1，于是加到4个5。开会输，继续抬也很困难；Sol按40.7%的朴素概率开牌，实际恰好4。
- 第6局：Sol只剩一骰并报2个3。Opus根据低点数并列规则判断Sol那颗是3而非万能1；自己的 `[3,1,6,1]` 提供三个有效3，于是报4个3。当前报价恰好成立，而所有更高合法报价都不成立，形成“开也输、抬也输”的闭合陷阱。

第二场至少5条行动留档显式引用第一场；这是跨场适应的直接证据，而不是赛后故事。

## Opus也不完全可靠

丰富推理没有消除事实与判断风险：

- 终局总结声称自己“系列中输了三局”，而权威记录是每场各输第3局，共两局；
- 它多次把短样本规律写成接近确定性的手牌解码，第二场第3局就因选择了错误候选手牌而开错。

这再次验证项目的“场合律”：模型写判断可以错，裁判事实必须由引擎写。长推理能形成更深策略，也能形成更长、更自信的错故事。

## 为什么2–0不能直接叫实力碾压

结果确实悬殊：小局总比分2–10，Sol八次开牌全错。但至少有四个限制：

1. 两场不是同种子换座镜像，运气没有被对冲；
2. Opus的生成预算远高于Sol；
3. 这是Agent系统对决，不能把Harness贡献归到模型权重；
4. 一旦Opus识别出Sol策略，BO3变成带路径依赖的宿敌赛，不再是独立同分布样本。

所以可支持的说法是：

> 在这两个种子和这套持续Session MCP中，Opus成功识别并利用了Sol的动作策略，Sol没有出现同等级的跨场适应。

不能支持的说法是：

> Claude Opus 5普遍比GPT-5.6 Sol更会玩游戏。

## 成本与时间

- Opus侧报告成本：$5.87；
- Opus：111,897 output token，3,157,323 cache-read input token；
- Sol：5,217 output token，988 reasoning token，900,822 input token中859,136为缓存输入。

这里不能用协调器的 `thinkMs` 比速度：Sol常在拿到观察结果后立即提交动作，模型此前的计划时间落在另一次调用里；Opus则常在观察后长时间推理再行动。该字段测的是“最后一份工具结果到动作提交”的间隔，不是完整模型耗时。

## 下一步实验

优先级从高到低：

1. **同种子换Agent席位**：再跑镜像BO3，抵消座位、首手和骰序；
2. **持续Session消融**：同样种子，一组每场新Session，一组连续Session，量化跨场记忆增益；
3. **关闭台词**：判断Opus是否读了Sol动作，还是也被自己说出的叙事推动；
4. **等成本或等延迟臂**：限制Opus预算，避免把21倍输出量直接当能力差异；
5. **定点状态重放**：抽取本次8个Sol误开位置，让两边重复采样，检验阈值策略和条件推断是否稳定；
6. **扩到至少10组镜像系列**：之后才能讨论稳定胜率或风味差异。
