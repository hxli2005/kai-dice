# 文章系列路线图

以下文章共享同一证据库，但各自回答一个独立问题。写作时必须链接本实验档案，并明确“小样本、Agent系统对决、非通用排名”。

## 文章一：模型没算错概率，它算错了问题

暂定标题：**《八次开牌全错：GPT-5.6 Sol 的数学为什么没有救它》**

核心论点：朴素的 `P(报价成立 | 自己骰面)` 忽略了 `对手为何选择这口报价`。一旦对手策略性选择强支撑报价，未条件化概率会系统性低估真价。

关键证据：Sol 8次开牌朴素成立率与0/8命中；第一场第4局、第二场第5/6局的条件选择。

必须避免：把0/8写成一般能力缺陷。至少补一组定点重复采样后再发表强结论。

## 文章二：没有画像，AI也会在同一Session里学会读人吗

暂定标题：**《没有记忆工具，Opus 如何在两场骰局里破解对手》**

核心论点：持续Session本身能承载跨场适应，但“保留历史”与“形成可执行的对手模型”是两回事。Opus显式引用第一场5次，Sol为0。

关键证据：最长花色+1、低点数并列、开牌阈值三条假设如何进入第二场动作；终局闭合陷阱。

必须避免：声称结构化画像无用。当前实验没有做“自由上下文 vs 结构化画像”的对照。

## 文章三：你测到的是模型，还是Agent Harness

暂定标题：**《同一个MCP，不是同一道题：Codex vs Claude Code 的公平陷阱》**

核心论点：即使游戏接口完全相同，默认系统提示词、工具调度、上下文压缩、输出预算和恢复策略仍会改变任务。此次Opus输出量约为Sol的21倍。

关键证据：同MCP与同引擎的可控部分；两边资源、说话频率、工具循环和stale恢复差异。

文章价值：承接现有《你测到的是模型，还是Harness？》，从模型API擂台推进到通用Agent产品对决。

## 文章四：让两个通用Agent真正坐到一张桌

暂定标题：**《从 observe/act 到 MCP：我怎样让 Codex 和 Claude Code 打完一场大话骰》**

核心论点：Agent原生游戏接口的关键不是长Prompt，而是权威引擎、席位投影、状态版本、可审计当手留档和降级隔离。

关键证据：两个固定席位MCP、陈旧状态拒绝、SSE直播、决定性回放、同Session BO3。

适合读者：游戏开发者、Agent工具作者、MCP开发者。

## 文章五：长程Agent的能力账与成本账

暂定标题：**《一组BO3花了多少：长程游戏Agent的真实成本结构》**

核心论点：能打完不等于能产品化。Opus的深策略伴随$5.87成本与11万输出token；Sol更精简，却没有表现出同等级对手建模。

关键证据：两边token、缓存、动作数、两场耗时与思考字段的测量陷阱。

必须避免：直接用协调器 `thinkMs` 比模型速度；该指标在两个Harness中的采样边界不同。

## 建议发布顺序

1. 文章四：先交代系统与可信度；
2. 文章一：发布最清晰的方法论发现；
3. 文章二：讲最有戏剧性的长程适应；
4. 文章三：抬高到Agent评测方法；
5. 文章五：用成本收束产品边界。

## 发表前补证据清单

- 镜像BO3至少一组；
- 连续Session vs 每场新Session消融；
- 8个关键状态每边重复采样；
- 关闭台词对照；
- 至少记录一次相同预算或相同延迟配置。

完成这些之前，文章可以作为开发实录和方法论案例发表，但所有标题、导语和结论都必须使用“这张桌、这次配置、这两个种子”的限定。
