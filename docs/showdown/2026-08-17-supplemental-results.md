# Liar's Dice Agent Showdown：第一批补充实验结果

日期：2026-08-17

## 结论先行

独立种子复现和同种子换边都没有改变系列胜者：Claude Opus 5 在三组持续 session BO3 中均以 2–0 战胜 `gpt-5.6-sol`。在原种子的镜像对照里，Opus 换到 A 席后仍赢下两场，因此原结果不能用“B 席、后手或 B 席拿到更好的私骰”单独解释。

但这仍是 **Agent system 对 Agent system** 的小样本比较，不是纯模型排行榜。双方的 token、工具调用行为和 CLI 编排差异很大；镜像实验还发生了 Sol 重复非法提交风暴，必须和策略结果一起报告。

## 三组结果

| 实验 | 模型映射 | 种子 | 系列 | 每场结果 |
|---|---|---|---|---|
| E0 原实验 | Sol=A，Opus=B | 73019426、73019427 | Opus 2–0 | Opus 剩 4 骰；Opus 剩 4 骰 |
| E1 独立复现 | Sol=A，Opus=B | 84627135、84627136 | Opus 2–0 | Opus 剩 5 骰；Opus 剩 3 骰 |
| E2 同种子镜像 | Opus=A，Sol=B | 73019426、73019427 | Opus 2–0 | Opus 剩 5 骰；Opus 剩 2 骰 |

E0 与 E2 构成配对换边：引擎种子、每场先手和席位私骰序列保持不变，只交换哪个 Agent 控制 A/B。四个配对场次全部由 Opus 控制的席位获胜。

## 最稳定的行为差异：challenge 选择

| 实验 | Sol challenge | Opus challenge |
|---|---:|---:|
| E0 | 0 / 8 | 2 / 4 |
| E1 | 2 / 10 | 2 / 2 |
| E2 | 2 / 8 | 4 / 5 |
| 合计 | **4 / 26（15.4%）** | **8 / 11（72.7%）** |

这里的“命中”只表示挑战后发现当前报价不成立。样本数很小，不能外推成总体胜率；但三组实验的方向一致。

Sol 并非不会算概率。它能开掉明显虚价，也在镜像第二场前两局连续命中。主要问题更接近 **条件化错误**：它经常按随机未知骰计算报价成立概率，却没有充分考虑“Opus 在看到自己手牌后主动选择了这个高报价”。于是高而有支撑的报价被当成普通高报价，挑战阈值过于宽松。

Opus 的强项也不是永远正确，而是把三类证据结合起来：

1. 自己手牌给出的物理上限；
2. 对手刚刚避开的点数与选择的加价路径；
3. 前场已经观察到的 challenge 倾向。

## 镜像实验的关键轨迹

第一场 Opus 5–0 清台：

- Opus 三次抓到确定或近确定不成立的 Sol 报价；
- Sol 对 Opus 的 `6×4` 开牌，实际恰好 6，报价成立；
- Opus 把 Sol 多次越过物理上限的行为写入第二场判断。

第二场 Sol 先以两次正确 challenge 建立 5–3 骰领先，随后 Opus 连续用有手牌支撑的报价反击：

- `4×3`，实际 4；
- `3×5`，实际 3；
- 再次 `3×5`，实际仍为 3；
- `3×3`，实际 3；
- 终局 `2×5`，实际 2。

这些报价都被 Sol challenge，且都恰好成立。中间 Opus 也误开过 Sol 的 `3×3`，证明其判断并非完美。

## 跨场调整的可见证据

机械启发式只统计第二场 `belief/say/note` 中显式提到前场的决策：

| 实验 | Sol | Opus |
|---|---:|---:|
| E0 | 0 | 5 |
| E1 | 0 | 2 |
| E2 | 0 | 3 |

这不能证明隐藏记忆，也检测不到隐式调整；它只能说明日志里是否明确引用前场。三次 BO3 中，Opus 都在第二场显式复用第一场信息，Sol 都没有留下同类文字证据。

## 镜像实验协议异常

E2 第一场第 2、3 小局，Sol 两次把首报最低数量写成 `1`，而规则与工具 schema 要求至少 `2`。它随后分别在同一状态重复提交 601 次和 492 次：

- 引擎全部以 `ILLEGAL_ACTION / bid off ladder` 拒绝；
- 两个风暴合计造成 1093 次拒绝，但只对应 **两个重复错误模式**；
- 另有 7 次普通陈旧状态拒绝；
- 非法请求没有改变引擎状态，Agent 后来恢复并完成比赛；
- 大量失败调用和 stderr analytics queue 警告污染了延迟、context 与资源消耗。

因此 E2 的合法动作和胜负是确定、可回放的，但它不是零协议异常的干净策略样本。这个异常本身是有价值的 Agent 鲁棒性结果：工具 schema 已声明 `minimum: 2`，引擎也返回明确拒绝，Sol 仍进入高速重复调用。

## 资源口径

三组 BO3 合计：

- Sol：4,177,026 input token，其中 3,966,976 为 cached input；19,041 output；CLI 未返回美元费用。
- Claude Code：302,757 output token；回执费用合计约 **$17.63**，另有缓存读写与极少量内部 Haiku 辅助开销。

这说明当前结果包含明显的推理资源与 Agent 实现差异。胜负可以报告，不能据此声称“同成本下 Opus 一定更强”。

## 验收

- E1：两场 replay 分别 `44/44`、`63/63` 事件逐项一致；双方 exit 0；131 条 Claude gameplay 回执均为 `claude-opus-5`。
- E2：两场 replay 分别 `44/44`、`74/74` 事件逐项一致；双方 exit 0；149 条 Claude gameplay 回执均为 `claude-opus-5`。
- 两场均无超时或 fallback 接管。

## 下一检查点

最有信息增益的下一项不是继续堆普通 BO3，而是：

1. 先给实验运行器增加“重复非法工具调用风暴”失效标记，防止受污染样本混入主结果；
2. 做 E3：每场重开 session，直接测试 Opus 的跨场显式建模是否贡献胜率；
3. 若 E3 仍有差异，再做 E4：关闭自然语言发言，区分动作信号和话术信号。
