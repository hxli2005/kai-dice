# 心机 Claude 对战老实人 GPT：吹牛比赛

### 一场 MCP 双席对局的工程记录，附一次 3ms 的破案

> 对局为 Codex CLI（`gpt-5.6-sol`）与 Claude Code（Opus 5）经同一权威引擎的真实比赛。文中数字复算自原始 `run.json` 与双侧 session 日志，全部事件可由种子决定性重放。结论只适用于这套设置，不构成通用模型排名。

---

我把 Codex CLI 和 Claude Code 接到同一个大话骰引擎上，让它们用 MCP 打了三组三局两胜（BO3）。Claude 全赢了：2–0、2–0、2–0，开牌命中 8/11，对面 4/26。

比分本身两句话就说完了。值得展开写的有三样：一张让两个 Agent 没法作弊、事后可审计的牌桌怎么搭；数据里两组反直觉的数字；还有一次差点冤枉模型的事故。

## 一、牌桌怎么搭

大话骰规则六十秒：两边各五颗骰，只看得到自己的。轮流报"全桌至少有 N 个 X 点"，轮到你只能加码或开牌；开牌后数量够，开的人掉一颗骰，数量不够，报的人掉，先掉光的输。1 默认是万能骰。

规则好写，麻烦在于让结果可信。Codex 和 Claude Code 是两家的 CLI，各自带着自己的系统提示词和工具循环。要让比赛有分析价值，至少得保证三件事：谁也看不到对面的骰子；裁判没有偏心的通道；赛后引用的"心理活动"确实写于行动当时，没被事后加工。

架构是一个进程内的规则引擎，配一个只绑 127.0.0.1 的 HTTP 协调器，两个 stdio MCP 席位服务器负责转发：

```text
 Codex CLI (gpt-5.6-sol)       Claude Code (Opus 5)
       |  stdio MCP                 |  stdio MCP
       v                            v
  [seat-mcp A] --token A--+  +--token B-- [seat-mcp B]
                          |  |
                          v  v
              +------------------------+
              | coordinator @127.0.0.1 |
              |  - createMatch engine  |
              |  - stateId concurrency |
              |  - run.json audit log  |
              +-----------+------------+
                          | SSE
                          v
                    [ /spectate ]
```

几条关键设计：

- **token 在进程启动时绑死席位。** 工具参数里没有 seat 字段，客户端想冒充对面，连填的地方都没有。
- **信息隔离做在 schema 层。** 席位视图复用游戏产品的 `observe()` 投影，返回的 JSON 里没有对手骰面这个字段。比起在提示词里写"请勿偷看"，把字段拿掉要实在得多。
- **动作走乐观并发。** 每份观察带 `stateId`，提交时校验，过期直接 409。两边并发看骰会撞出这类冲突，每次运行 0–7 次，全在拒绝日志里。
- **心理活动当手落盘。** 每个动作要求同时提交一段私有 `belief` 和一句可选的公开 `say`。`belief` 随动作原子写入，对手看不见，赛后改不了。本文引用的所有"它当时怎么想"都出自这里。
- **响应时间脱敏。** 原始毫秒只进审计文件，席位和观战页只能看到 slow/fast 两档。不做这层，响应时间可以当侧信道用。
- **骰面走 commit-reveal。** 每局开始先公布双方骰面的承诺哈希，摊牌时可验，裁判想事后改骰也没有机会。
- **开牌动作必须带断言。** challenge 要求写 `assert: "current_bid_is_false"`，缺字段判非法。这条来自早前一组定点重放实验：同一个模型，把"开牌"从一个光秃秃的动词换成一句要亲手写出来的断言，必输局面的误开率从 23% 降到 2%。工具 schema 会实质性影响模型的行为，这里算一个实测例子。

两席收到的系统说明和任务提示词逐字相同，各自在隔离的临时目录运行、忽略用户级配置。一个 session 打完整组 BO3，跨局记忆属于被测机制。两家 CLI 内部的提示词和调度我控制不了，所以参赛单位从头到尾都按"Codex+Sol"和"Claude Code+Opus"两套系统来算，后面的结论也都是这个口径。

## 二、这些数字凭什么可信

跑完之后做了几步核验：

- **决定性重放。** 引擎给定种子和动作序列输出唯一的事件流。核验工具从 `run.json` 取出种子和已接受动作，重放出全部事件再逐项 diff。五次运行、8 场、432 个事件全部一致，连耗时字段都对得上。
- **拒绝全量留档。** 非法动作改不了牌局，但每一次都记录在案，含动作原文和时间戳。第五节会用到它。
- **模型身份靠回执。** Claude 侧的 gameplay 回执全部是 `claude-opus-5`；两侧的 token、费用、缓存读写都入档。
- **文件级哈希冻结。** 每个实验目录附 SHA256SUMS。

工作流大概是：

```bash
# 跑一组同 session BO3；换边镜像只需改 --codex-seat
node scripts/mcp/run-showdown.mjs --best-of 3 --seed 73019426 \
  --codex-seat A --codex-model gpt-5.6-sol --claude-model opus

# 事后核验：种子＋动作序列重放全部事件并逐项比对
node scripts/mcp/replay-showdown.mjs docs/showdown/<run-dir>
```

## 三、结果

| 实验 | 配置 | 系列 | Sol 开牌 | Opus 开牌 |
|---|---|---|---|---|
| E0 | Sol=A，持续 session BO3 | Opus 2–0 | 0/8 | 2/4 |
| E1 | 同配置，全新种子 | Opus 2–0 | 2/10 | 2/2 |
| E2 | 同 E0 种子，**模型换边** | Opus 2–0 | 2/8 | 4/5 |

E2 把 E0 的种子原样拿来，只交换两个 Agent 控制的席位。四个配对场次全部跟着 Opus 走，"B 席好""后手好""骰运好"这些解释可以划掉了。补一句精确的：换边控制到随机流级别——第 1 局双方手牌与原实验逐字相同，之后随掉骰数量错位。

统计开牌记录时出来一组怪数字。三组合计，Opus 被开牌的报价 22/26 是真的；Sol 被开牌的报价 8/11 是假的。按人设，吹牛的应该是"心机"那位，实际上桌上说真话最多的就是它。

## 四、Sol 输在哪

Sol 的打法从留档里能直接总结出来：看骰；在自己最长的花色上报"自有数量+1"；对面报价过来，按二项分布算个成立率，低于阈值就开。流程干净稳定，单看每一步都没毛病。

毛病在这套流程对对手的假设上。它算的是"如果对面的骰子随机分布，这口价成立的概率是多少"。可对面的报价从来不是随机抽的——Opus 只在自己手牌撑得住的时候把数量推高，"它选择报这口价"这件事本身就带信息。Sol 的公式里没有这一项，于是一次次用正确的算术得出错误的判断。

Opus 把这个缺口用到了极致。它先从 Sol 的首报规律反推手牌（"最长花色+1"等于自报家门），再摸清 Sol 的开牌阈值，然后专门制造那种按随机假设算会显得可疑、实际必成立的报价，钓 Sol 来开。最夸张的一段连续三轮：真价报在成立线边缘，Sol 三次开牌，三次撞在真价上。其中一轮 Opus 还说了句"你已经两次绕过我的 5，我不觉得这是巧合"——说的是实话，Sol 照样开，照样输。

Opus 也有翻车记录。它误开过一次 Sol 的边缘真价，掉了一颗骰。它的对手模型时不时算错，只是一直在更新。

跨场的差距同样清楚。第二场行动留档里对第一场的显式引用，Opus 三组分别是 5、2、3 次，Sol 三组都是 0。记忆条件两边一样，用起来的只有一边。

## 五、1093 次非法提交的破案

换边那组出过一次事故。Sol 在两个首报状态把数量写成 1（规则和工具 schema 的下限都是 2），被拒之后重复提交，两波合计 1093 次。

我第一反应也是"模型失控了"。好在拒绝日志是全量留档的，时间戳一拉就露馅：601 次挤在 22 秒里，中位间隔 3ms；另外 492 次挤在 12 秒里，同样 3ms。模型推理一次怎么也要几百毫秒起步，3ms 一发只可能是重试循环在打。再对照独立种子那组：同样的 `count:1` 错误也出现过一次，被拒一次就改了。所以这笔账要分开记：把下限写成 1 是模型犯的错；把它重复六百遍是 CLI 的重试机制干的。

假如没有逐条留档，聚合报表上只会剩一句"Sol 提交非法动作 1093 次"，顺理成章就写进"它慌了"之类的叙事里。给模型定性之前，值得把这个问题固定成流程：只换 harness，这个行为还在吗？

这次也暴露了协调器欠的债。它应该有个断路器：同模式的拒绝折叠计数、加退避、给样本打污染标记。这回它硬扛住六百连击没有错判，下次不该再让它硬扛。

## 六、账本

**参赛的是两套系统，混杂里最大的一项是算力。** Opus 侧共生成约 30 万 output token，Sol 侧 1.9 万，差 16 倍，回执费用 $17.63。这里面"会想"和"多想"各占多少，目前分不出来。

**样本很小。** 三组 BO3 共六场，而且 BO3 内两场并不独立——跨局记忆本来就是被测机制。

**还有一条反向的暗线。** 用 Codex 默认模型打的第一场（没指定 sol，也没有 BO3），小局打到 5–4，接近得多。悬殊比分全部出现在"固定套路 × 连续 session"的组合里，差距看起来是后天学出来的。这句话对不对，实验能验。

排下来的下一批实验：每场重开 session，量一量跨局记忆到底贡献多少胜率；关掉台词，把动作信号和话术分开；压平算力预算再比一次；从关键局面定点重放，区分稳定策略和采样运气。每一项都对应上面某个还没关死的口子。

## 七、收尾

做题式的评测里条件给全，算对就行。牌桌上多了一个会适应你的对手，题目本身会被对面改写。Sol 全程在解概率题；Opus 花了大量 token 琢磨"它为什么报这口价，我该让它看见什么"。两边打的其实不是同一个游戏。

整场比赛我最喜欢的还是那三轮：心机鬼把真话说了三遍，老实人一遍都没信。
