# 心机 Claude 对战老实人 GPT：吹牛比赛

### 让 Codex 和 Claude Code 公平打一场大话骰，难的不是牌桌，是可信度

> 对局为 Codex CLI（`gpt-5.6-sol`）与 Claude Code（Opus 5）经同一权威引擎的真实比赛。文中全部数字复算自原始 `run.json` 与双侧 session 日志，全部事件可由种子决定性重放。结论只适用于这套设置，不是通用模型排名。

---

先把结果放这：三组三局两胜制（BO3）系列赛，Claude 全部 2–0；开牌命中率 **73%（8/11）对 15%（4/26）**。

但这篇不是战报。真正值得写的是三件事：

1. 怎么搭一张让两个通用 Agent **无法作弊、事后可审计**的牌桌；
2. 数据里两个反直觉的发现——"心机"的一方靠说真话赢，以及一场 1093 次非法提交的"事故"，主犯根本不是模型；
3. 这类 Agent 对决的结论边界在哪——哪些话数据撑得住，哪些撑不住。

## 一、赛制：两个 Agent 怎么坐上同一张桌

大话骰规则六十秒：两边各五颗骰，只见自己的。轮流报"全桌至少 N 个 X 点"，只能加码或开牌；开牌后数量够，开的人掉骰，不够，报的人掉，先掉光者输。1 默认是万能骰。

难点不在规则，在公平。两个 Agent 是两家公司的 CLI，凭什么相信它们没偷看对方的骰子、没被裁判偏袒、赛后复盘的"心理活动"不是编的？

架构长这样：

```text
 Codex CLI (gpt-5.6-sol)       Claude Code (Opus 5)
       |  stdio MCP                 |  stdio MCP
       v                            v
  [seat-mcp A] --token A--+  +--token B-- [seat-mcp B]
                          |  |
                          v  v
              +------------------------+
              | coordinator @127.0.0.1 |
              |  - createMatch engine  |
              |  - stateId concurrency |
              |  - run.json audit log  |
              +-----------+------------+
                          | SSE
                          v
                    [ /spectate ]
```

一个进程内的权威规则引擎，配一个只绑本机的 HTTP 协调器；两个 stdio MCP 席位服务器只做转发。每一条设计都对应挡住一类具体的污染：

- **席位不出现在工具参数里。** token 在进程启动时绑死席位，客户端连"声称自己是谁"的机会都没有。公平由拓扑保证，不靠提示词承诺。
- **信息隔离在 schema 层。** 席位视图复用游戏产品的 `observe()` 投影——返回结构里根本没有对手骰面字段。不是"提示词里说了别看"，是数据里没有。
- **动作走乐观并发。** 每个观察带 `stateId`，陈旧状态提交一律 409 拒绝并留档。并发看骰产生的少量冲突（每次运行 0–7 次）全部可查。
- **心理活动是当手留档，不是赛后采访。** 每个动作必须同时提交 `belief`（私有判断）和可选的一句公开 `say`。留档随动作原子落盘，对手看不见，赛后也改不了——文中引用的"心理活动"全部来自行动那一刻。
- **时延脱敏。** 原始毫秒只进审计文件；席位和观战端只能看到 slow/fast 两档分类。防的是拿响应时间当侧信道读对手状态。
- **骰面走 commit-reveal。** 每局开始先公布双方骰面的承诺哈希，摊牌时可验——裁判自己也没法事后改骰。
- **开牌动作强制带语义断言。** challenge 必须写 `assert: "current_bid_is_false"`，缺字段判非法。这是之前一轮定点重放实验的产物：只把"开牌"从一个动词变成一句必须亲手写出的断言，某模型在"必输局面"的误开率就从 23% 掉到 2%。工具 schema 不是管道，是题面的一部分。

两席收到的系统说明与任务提示词逐字相同，各自在隔离的临时目录运行、忽略用户级配置。一个 session 打完整组 BO3——跨局记忆本身是被测机制之一。

**坦白局限：两边的 CLI 本体没法对齐。** 默认系统提示词、上下文管理、重试策略都是各家自己的。所以这从一开始就是 **Codex+Sol 对 Claude Code+Opus 两套系统的对决**，不是裸模型对比。这个口径贯穿全文。

## 二、证据链：为什么这些数字可以信

跑完只是开始，可审计才算完成：

- **决定性重放。** 引擎给定种子和动作序列是纯函数。留档工具从 `run.json` 取出种子＋已接受动作，重放全部引擎事件并逐项 diff——五次运行、8 场、432 个事件**严格一致**（连耗时字段都逐字复现）。
- **全量拒绝留档。** 非法动作不改变牌局，但每一次都记录在案（后面会看到这有多重要）。
- **模型身份用回执核对。** Claude 侧全部 gameplay 回执均为 `claude-opus-5`；Codex 侧 usage 从 CLI 事件流提取。token、费用、缓存全部入档。
- **文件级哈希冻结。** 每个实验目录附 SHA256SUMS。

复现工作流大致是：

```bash
# 跑一组同 session BO3，换边镜像只需改 --codex-seat
node scripts/mcp/run-showdown.mjs --best-of 3 --seed 73019426 \
  --codex-seat A --codex-model gpt-5.6-sol --claude-model opus

# 事后核验：种子＋动作序列重放全部事件并逐项比对
node scripts/mcp/replay-showdown.mjs docs/showdown/<run-dir>
```

## 三、结果：数字比比分有意思

| 实验 | 配置 | 系列 | Sol 开牌 | Opus 开牌 |
|---|---|---|---|---|
| E0 | Sol=A，持续 session BO3 | Opus 2–0 | 0/8 | 2/4 |
| E1 | 同配置，全新种子 | Opus 2–0 | 2/10 | 2/2 |
| E2 | 同 E0 种子，**模型换边** | Opus 2–0 | 2/8 | 4/5 |

E2 是关键对照：引擎种子、逐场先手、随机流全部复用 E0，只交换哪个 Agent 控制 A/B 席。四个配对场次全部跟着 Opus 走——**"座位、先手或骰运好"这类解释被直接排除**。（严格说，换边控制到随机流级别：第 1 局双方手牌与原实验逐字相同，之后随掉骰数量错位。）

真正的杀器藏在另一组数字里。三组比赛合计：

- **Opus 被开牌的报价，22/26（85%）是真的；**
- **Sol 被开牌的报价，8/11（73%）是假的。**

这场吹牛比赛里，吹牛吹得多的是"老实人"，说真话的是"心机鬼"。

## 四、复盘：老实人不是算错了数，是算错了题

Sol 的策略稳定得像模板：看骰，在自己最长的花色上报"自有数量+1"；对面报价来了，按二项分布算成立率；低于阈值就开。

两个致命破绽。第一，"最长花色+1"意味着**它的首报在诚实汇报手牌**——Opus 第一场结束就把这条规律写进留档，第二场直接当解码器用。

第二个破绽深一层。Sol 的概率计算回答的是：

> 如果对手的骰子是随机未知的，这口价成立的概率是多少？

但牌桌上真正的问题是：

> 对手**看过自己的牌、又主动选择报出这口价**之后，它成立的概率是多少？

这是两道不同的题。Opus 从不随机报价——它专挑自己手牌已经强支撑的点数，把数量推到"按随机假设算会显得可疑"的位置，再钓 Sol 来开。"对手选择了这个动作"本身就是证据，Sol 的公式里恰好没有这一项。于是出现了全场最戏剧的一段：Opus 连续三轮把真价报在成立线边缘，Sol 连续三轮开牌，连续三轮撞在真价上——其中一轮 Opus 还当面说"你已经两次绕过我的 5，我不觉得这是巧合"。

说的是真话。对面不信。

（Opus 也不是开了天眼：它同样误开过一次 Sol 的边缘真价并掉骰。区别是它错完继续修正对手模型，而不是弃疗。）

跨场维度同样悬殊。机械统计第二场行动留档中对第一场的显式引用：Opus 三组分别 5、2、3 次，Sol 三组全部 **0 次**。同 session 给了双方同等的记忆条件，只有一方把历史变成了武器。

## 五、事故解剖：1093 次非法提交，主犯不是模型

换边实验里出过一次协议事故：Sol 在两个首报状态把最低数量写成 1（规则与工具 schema 都要求 ≥2），被引擎拒绝后重复提交，两波合计 **1093 次**。

第一反应当然是"模型失控了"。但拒绝记录全量留档，时间戳一查：

- 601 次发生在 22 秒内，中位间隔 **3ms**（27 次/秒）；
- 492 次发生在 12 秒内，中位间隔 **3ms**（40 次/秒）。

没有任何 LLM 能用 3 毫秒推理一次。把首报下限写成 1，是模型的错——同款错误在另一组实验也出现过一次，**被拒一次就改了**；把一个错误重复六百遍，是 CLI 重试循环的行为。

这个拆分很重要。如果只看聚合数字，"Sol 疯狂提交非法动作 1093 次"会被自然地读成模型属性，写进"它慌了"这类叙事。逐条留档＋时间戳才让归因有了地板。给模型定性之前，永远值得先问一句：**只换 harness，这个行为还在吗？**

（顺带的工程教训：协调器还欠一个风暴断路器——同模式拒绝应该折叠、退避，并给样本打污染标记。裁判抗住了六百连击没错判一次，但让它挨打不是设计。）

## 六、账本：这些数据不能说什么

- **不能说"Claude 模型比 GPT 模型强"。** 系统对决口径贯穿全文；最硬的混杂是算力——Opus 侧共生成约 30 万 output token，是 Sol 侧（1.9 万）的 **16 倍**，回执费用 $17.63。赢的里面多少是"会想"、多少是"多想"，还没分开。
- **样本很小。** 三组 BO3 共六场，且 BO3 内两场不独立（跨局记忆正是被测机制）。
- **有一条反向暗线。** 用 Codex 默认模型（非 sol）打的第一场，小局打到 5–4，接近得多。悬殊比分全部出现在"固定策略 × 持续 session"的组合下——差距更像是**被学出来的**，而不是天生的。

下一步实验也由此排定：每场重开 session（隔离跨局记忆的贡献）、禁台词只留动作（分离话术与动作信号）、等成本臂（把 16 倍算力压平再比）、定点状态重放（区分稳定策略与采样波动）。每一项都在检验上面某句话会不会被推翻。

## 七、收尾

我们习惯用做题评测模型：条件给全，看谁算得对。牌桌不一样——对手会观察你、适应你、故意改变你要解的题。

Sol 全程在算"这口价成立的概率"；Opus 在算"**它为什么偏偏报这口价，以及我该让它看见什么**"。从第一个问题到第二个问题，是从计算器到玩家的那一步。

而整场比赛最精彩的，不是谁说了一句漂亮的假话——

是心机鬼连着说了几次真话，老实人始终不信。
