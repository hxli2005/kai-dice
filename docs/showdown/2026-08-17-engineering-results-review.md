**核验中的新发现（既有文档未载）**：

1. **风暴的放大环节不是模型**。两次风暴的拒绝时间戳中位间隔 **3ms**（601 次 22 秒＝27.3 次/秒；492 次 12 秒＝40.5 次/秒）。没有模型能以 3ms 一次的节奏逐次生成决策——首次 `count:1` 非法报价是模型的错，把它重复六百次是 Codex CLI 侧重试循环的行为。
2. **同一个模型错误在 E1 也出现过，且一次即愈**：E1 第二场第 5 局 Sol 同样提交 `count:1`（`bid off ladder`），被拒一次后即改为合法动作。「低于下限的报价」是 Sol 的系统性倾向（两次实验、三个状态），「风暴」才是 E2 特有的 harness 放大。
3. **镜像的「私骰跟座位走」是随机流级别的控制**：两局共用同一条按 A→B 顺序消费的随机流。第 1 局双方手牌与 E0 逐字相同；此后局随掉骰数量错位（实测 E2 的 A 手牌恰为 E0 的 A 手牌加前缀延长、B 手牌为流的错位切片）。配对对照依然成立，但文章表述不应写成「每一局手牌都相同」。
4. **双方全程零 blind、零 raise**：五次运行合计，Codex 动作分布 peek 51／bid 58／challenge 35／宣斋 1，Claude peek 51／bid 56／challenge 16／宣斋 3。两个 Agent 都没碰声明系动作，规则空间的这一半完全没被探索。

## 二、工程：这套系统的可信度从哪来

架构一句话：**一个进程内权威引擎＋本机 HTTP 协调器，两个 stdio MCP 席位服务器只做带 cursor 的转发，Codex／Claude CLI 各持一枚不可跨席的 bearer token。**

### 值得保留的八个设计决定

每一条都对应挡住了一类具体的评测污染：

1. **席位不出现在工具参数里**（token→seat 绑定在进程启动时）——客户端无法伪装身份，「公平」由拓扑保证而非提示词承诺。
2. **schema 级信息隔离**——席位视图复用产品 `observe()` 投影，结构里根本没有对手骰面字段。
3. **stateId 乐观并发**——陈旧动作一律 409 拒绝并留档；各场 4–7 次 stale 全部可查、可归因（并发看骰）。
4. **当手留档与公开发言分离**——`belief`/`note` 随动作原子提交、对手不可见，反事后叙事；`say` 单独转发并明示「不可信言论」。
5. **时延脱敏**——原始毫秒只进审计文件，席位与观战只见 slow/fast 分类，掐掉计时侧信道（`thinkMs` 语义在 review.md 里也如实交代了只测「工具结果→提交」）。
6. **commit-reveal**——roundStart 先发骰面承诺哈希，reveal 可验（本次抽验 10/10），引擎无法事后改骰。
7. **观战层只拼两个合法席位投影**，人机模式直接关闭 `/spectate`——不为直播开引擎后门。
8. **两席 instructions 与任务 prompt 逐字相同**，各自隔离临时 cwd、忽略用户配置——「接口公平」口径在可控范围内成立。

测试面：`test/mcp-showdown.test.js`＋`test/mcp-analysis.test.js` 共 10 条，覆盖席位隔离、令牌越权、陈旧状态、stdio 协议、SSE 直播、人机越权、BO3 换场与完整终局，本次实跑 **10/10 通过**。`analyze-showdown.mjs` 的认识论纪律也好：启发式自带 `interpretation` 字段声明「只算显式文字引用，不能证明记忆」，`--out` 拒绝覆盖归档。

### 缺口（按修复优先级）

- **G1 整套工作未入版本库**。`scripts/mcp/`、`docs/showdown/`、两个测试文件全部 untracked。目录里有 SHA256SUMS，但哈希本身没有版本锚，「证据冻结」缺最后一环，也不符合 CLAUDE.md 第 0 条「小步提交」。
- **G2 重放验收原先没有工具**。「44/44 事件一致」只存在于 summary/SYNC 散文里；README 声称 `metadata.json` 含「验收结果」，实际 schema 里没有该字段（文档漂移）。本次已补 `scripts/mcp/replay-showdown.mjs`（8/8 场验证通过，exit code 可进 CI）；建议 runner 收尾时直接调用它并把结果写进 `metadata.json`。
- **G3 无拒绝风暴断路器**。同一 stateId 同一动作被拒 601 次，而且**每次拒绝都全量重写 run.json**（E2 最终 488K，风暴期累计磁盘写入约数百 MB）。建议三件套：同模式拒绝运行时折叠计数（analyze 里的 pattern 概念前移）、对重复拒绝指数退避或改发 429、超过阈值给该场贴「受污染样本」失效标记——supplemental 自己也把失效标记列为下一步第 1 条，这里补上具体形态。
- **G4 metadata 的 agent↔seat 映射直到 schema 2 才有**。E0（schema 1）复算时只能从 labels 兜底推断席位；旧目录建议补写一份 sidecar，避免后续统计脚本各自造轮子。
- **G5 跨场引用正则的语言盲区**。中文标记只有三个模式；SYNC Q105 刚记过「自然语言语义分类不要用正则」的教训。现在的正确用法是把它当**下界**读（文档已这么用），不要在文章里让它承担超过下界的重量。

## 三、结果：赢的不是算力，是条件化——以及一处需要拆开的归因

### 3.1 全景（全部复算）

| 运行 | 形态 | 结果 | Codex 开牌 | Claude 开牌 |
|---|---|---|---|---|
| 首场 seed 20260817（模型＝CLI 默认，非 sol） | 单场 9 小局 | Claude 胜，小局 5–4 | 3/7 | 1/2 |
| 单场 41782963（sol vs opus） | 单场 | Claude 5–0 清台 | 0/2 | 3/3 |
| E0 BO3 73019426 | Sol=A | Opus 2–0 | 0/8 | 2/4 |
| E1 BO3 84627135（独立复现） | Sol=A | Opus 2–0 | 2/10 | 2/2 |
| E2 BO3 73019426（同种子换边） | Opus=A | Opus 2–0 | 2/8 | 4/5 |

五次运行合计的核心不对称，两个方向互为镜像：

- **开牌命中**：Codex 7/35（20%），Claude 12/16（75%）；
- **自家报价被开后站住**：Claude 28/35（**80%**），Codex 4/16（25%）；
- Codex 开牌频率是 Claude 的 2.2 倍——「开太多」与「开不准」叠加，而 Claude 的高站住率说明它被开的价大多是**布好的真价**。

机制解释（review.md 已详述，底层数据本次核对无误）：Sol 回答的是「若对手骰子随机未知，这口价成立概率多少」，缺的条件是「**对手看过自己手牌后主动选择了这口价**」。Opus 的三步——识别 Sol 首报≈最长花色+1 的编码、识别其 ~40% 朴素概率开牌阈值、构造「开也输抬也难」的闭合报价——每一步都有行动当时留档与引擎事件双重印证，不是赛后故事。

### 3.2 首场的对照价值被低估了

唯一接近的对局（小局 5–4，Codex 开牌 3/7）恰好是**模型未知**（CLI default）且**无 BO3** 的那场。它不能直接和 sol 场次比（模型、赛制双重混杂），但它给「差距是学出来的」这个叙事提供了有趣的暗线：目前的证据结构里，悬殊比分全部出现在「可识别的固定策略×持续 session」组合下。E3（每场重开 session）正是检验这条暗线的实验。

### 3.3 风暴归因应当拆分——这正是你们自己框架的用武之地

《你测到的是模型，还是 Harness？》的判据是：**只改变 Harness，这个差异还会存在吗？** 用在 E2 风暴上：

- 模型层错误（会保留）：把首报下限写成 1。E1、E2 两次实验三个状态出现，系统性；
- Harness 层放大（换个重试策略就消失）：3ms 中位间隔的 1093 次重复提交。E1 里同一个错误一次被拒即愈。

supplemental 现在的表述「Sol 仍进入高速重复调用」把两层揉在一起，读者会把 601 次记在模型头上——这正是那篇文章里「DeepSeek 蒙报 40%」式的归因事故的镜像。建议发表前改写为两句话，并附速率证据。顺带说，「同一个模型错误在两套重试策略下的两种命运」本身就够写第六篇文章，它是 model-vs-harness 最干净的天然实验。

### 3.4 统计上能说与不能说

**能说**：三组 BO3 全 2–0，加两个单场共 8 场全胜；E0/E2 配对换边后四个配对场全部跟 Agent 而非座位走，「B 席/后手/骰运」的单独解释被排除；机制有当手留档＋可复算事件双重印证。在「接口公平」口径（同 prompt、同工具、同引擎）下，「这套 Claude Code+Opus 5 系统在此游戏里显著更强，且优势主要来自条件化推理与跨场对手建模」站得住。

**不能说**：模型通用排名。四个理由既有文档都列了，复盘确认它们都真实存在——① harness 不同（系统提示词、上下文管理、重试策略都不同，风暴就是活例）；② 计算预算 16 倍（302,757 vs 19,041 output token）；③ BO3 场间非独立（持续 session 正是被测机制）；④ n 太小。另补一条：**高光时刻是选出来的**——「三连真价被开」是全部对局里最戏剧的片段，等成本定点重放（E5）之前，无法区分「稳定策略」与「单次采样的漂亮波动」。

## 四、思考与下一步

对既定 E3–E5 计划的复核与补充：

1. **顺序维持「先修运行器再跑实验」**：G3 断路器＋失效标记先行（与 supplemental 检查点一致），否则下一个受污染样本还会混进主结果。重放验收已工具化（G2 完成），建议 runner 收尾自动跑。
2. **E3（session 消融）信息量最大**：跨场显式引用 10 vs 0 是现成的机制假设，E3 直接检验「记忆→胜率」的因果链。预注册预期：若消融后 Opus 优势明显收窄，则「学出来的差距」成立；若不变，优势主要来自单场内条件化，跨场叙事要降级。
3. **E4（关台词）的预期要先写下来**：Opus 的「报价编码」读的是动作序列，不需要台词。预期关台词后差异**不会消失**；若消失，那才是意外发现——预先写下这条能防事后解释。
4. **补一条等成本臂**：`--claude-model sonnet`（或压 effort）对阵满配 sol，或反向给 Codex 提高推理预算。不等成本的 2–0 已经把它能说的说完了；等成本臂才能把「条件化是能力还是预算」分开。
5. **统计纪律**：每臂预注册场数与停止规则；主指标从场级胜负换成 round 级（challenge 精度、被开站住率）——每场 5–8 个 round，样本效率高一个量级，而且这两个指标已被三组实验证明方向稳定。
6. **发表前的事实修订清单**：① 风暴归因拆分（§3.3）；② 镜像手牌表述精确化（§一.3）；③「六场全胜」旁并列首场 5–4 及其混杂条件，叙事更准确也更有张力；④ 文章引用「接口公平」口径声明，和 fairness 一文互链。
