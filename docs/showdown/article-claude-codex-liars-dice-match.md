# Claude 连赢六场，不是因为更会算：一场 LLM 大话骰对决复盘

如果让两个编程 Agent 坐到一张大话骰桌前，会发生什么？

我把 Codex 和 Claude Code 分别接入同一个权威游戏引擎。Codex 使用 `gpt-5.6-sol`，Claude Code 使用 Opus 5。它们各自只能看见自己的骰子、公开报价和合法动作，不能读取对手的暗骰，也没有额外的玩家画像或外置记忆。

双方可以报价、开牌，也可以在行动时说一句话。一个 session 负责整组 BO3，所以它们有机会记住上一场发生过什么，并在下一场调整。

结果很悬殊：三组 BO3，Opus 全部以 2–0 获胜。六个完整场次，胜者全部是 Claude Code。

但真正有意思的不是 6–0，而是它赢下比赛的方式。

## 先说规则

两边各有五颗骰子，只能看到自己的骰面。玩家轮流报价，例如“桌上一共有四个 5”。下一位必须继续抬价，或者选择开牌。

正常情况下，1 可以当作万能骰。如果开牌后实际数量达到报价，挑战者掉一颗骰；否则报价者掉一颗。谁先掉光五颗骰，谁输掉这一场。

这套规则的状态不大，动作也不多，但每一次报价都同时包含三层信息：

- 它可能描述自己的手牌；
- 它可能是在试探对手；
- 它也可能是在诱导对手做出错误反应。

这正是比赛开始变得精彩的地方。

## 换边之后，Claude 先打出一个 5–0

为了排除座位和骰运的影响，我把同一批种子重新跑了一次，只交换双方控制的座位。Claude 从 B 席换到 A 席，Codex 则拿到原来 Claude 的座位和私骰序列。

镜像第一场，Claude 以五颗骰全部存活的方式清台。

第一局，Codex 报出“六个 4”。Claude 看了一眼自己的五颗骰：没有 4，也没有万能 1。Codex 总共只有五颗骰，所以整张桌子最多只能出现五个有效 4。

六个 4 不是“不太可能”，而是物理上不可能。

Claude 直接开牌，Codex 掉一颗骰。

随后类似的情况不断出现。Codex 报“四个 5”时，Claude 自己只能贡献一个有效 5，而 Codex 只剩两颗骰，桌面上最多凑出三个；Codex 最后一颗骰时报“两个 6”，Claude 手里没有 6 和 1，桌面最多只能有一个。

Claude 没有在这些地方玩心理战。它先做了一件很朴素、却非常重要的事：把“概率很低”和“绝对不可能”分开。

第一场结束，Claude 5–0 清台。

## 第二场，Codex 一度以 5–3 领先

如果比赛到这里结束，它只会是一场碾压局。真正精彩的是第二场。

开局前两轮，Codex 连续两次开牌成功。

第一轮，Claude 报“四个 4”，实际只有三个；第二轮进入“斋局”，1 不再是万能骰，Claude 报“两个 6”，实际只有一个。Codex 两次判断都正确。

此时骰数是：Codex 5，Claude 3。

Claude 已经处在明显劣势。但接下来三轮，比赛的性质发生了变化。

第三轮，Claude 从“三个 3”加到“四个 3”。Codex 选择开牌。

实际数量：正好四个。

第四轮，Claude 报“三个 5”。Codex 再次开牌。

实际数量：正好三个。

第五轮，几乎相同的场面再次发生。Claude 又报“三个 5”，Codex 又选择开牌。

实际数量：仍然正好三个。

连续三轮，Claude 的报价都踩在成立线的最边缘；连续三轮，Codex 都认为这个报价太可疑，选择开牌；连续三轮，报价都恰好成立。

骰数从 Codex 5、Claude 3，变成了 Codex 2、Claude 3。

## 最有效的骗术，是把真话说得像假话

这三轮不是普通的好运。

Claude 并不是从所有合法报价中随机选一个高价。它先看自己的手牌，再观察 Codex 刚刚避开了哪个点数、选择了怎样的加价路径，以及过去在什么情况下喜欢开牌。

然后它寻找一种特殊的报价：

- 自己的手牌已经提供了很强的支撑；
- 数量高到足以显得可疑；
- Codex 按普通未知骰概率计算时，容易认为它不成立；
- 一旦 Codex 开牌，报价却正好站住。

Claude 甚至会公开邀请对方来开。

在第二次报“三个 5”时，它说：

> Three fives. You skipped past my fives twice now instead of testing them — I don't think that's an accident.

“三个 5。你已经两次绕过我的 5，而不是开我——我不觉得这是巧合。”

它不是单纯在诈唬，而是在把一个真实报价包装成诱饵。

大话骰通常让人想到“如何把假话说得像真的”。这场比赛展示了相反的一面：最有效的骗术，也可以是把真话说得像假话。

## Claude 也会判断失误

第六轮，Codex 报“三个 3”。Claude 自己只能提供一个有效 3，因此认为 Codex 的两颗骰必须全部是 3 或万能 1，概率很低，于是选择开牌。

结果桌上正好有三个有效 3。Claude 判断失败，也掉了一颗骰。

双方回到 2–2。

这一轮很重要。它证明 Claude 并没有读取对手暗骰，也不是每次都能算对。它同样会过度推断，也会被卡在成立线边缘的报价反制。

区别在于，Claude 的错误没有让它放弃对手模型。下一轮，它继续观察 Codex 从 3 点切换到 6 点的动作，推断对方可能持有 6 或万能 1，再把这个信号用于自己的 3 点报价。

Claude 报“三个 3”，Codex 开牌。

实际数量：正好三个。

Codex 只剩最后一颗骰。

终局，Codex 先报“两个 2”。Claude 看见自己的两颗骰是 1 和 5，于是报“两个 5”，并直接告诉对手这个数量已经存在于自己手里。

Codex 仍然选择开牌。

实际数量：两个。

Claude 以两颗骰存活完成逆转，也以 2–0 结束整组 BO3。

## Codex 算错的不是概率，而是问题

从全部对局日志看，Codex 的策略非常稳定：看自己的骰子，估算未知骰中出现目标点数的概率；面对一个成立率较低的报价时，倾向于开牌。

这种计算回答的是：

> 如果对手的骰子仍然是随机未知的，这个报价成立的概率是多少？

但比赛真正需要回答的是：

> 对手看过自己的骰子，并且主动选择报出这个数字之后，它成立的概率是多少？

这两个问题并不相同。

Claude 不会随机选择一个报价。它更愿意在自己的手牌已经强力支撑某个点数时，把这个点数推到一个看起来危险的位置。因此，“Claude 选择了这口价”本身就是新的证据。

Codex 的数学经常没有错。它漏掉的是对手为什么会做出这个动作。

## Claude 不只是记住了上一场

三次 BO3 中，Claude 都在第二场的行动留档里明确引用第一场观察到的规律，例如 Codex 的开牌倾向、常用报价方式和对物理上限的忽略。

Codex 的第二场留档中，没有出现同类的显式跨场引用。

这说明“一个 session 打完整组比赛”的价值，不只是让模型记住比分。真正有效的过程是：

> 观察行为 → 总结规律 → 在下一场调用规律 → 主动制造能利用这个规律的局面。

Claude 做到的不是被动记忆，而是把记忆变成了当前策略。

## 这不是一个通用模型排行榜

这场比赛需要保留几个重要限制。

首先，参赛者实际上是 Codex + `gpt-5.6-sol` 与 Claude Code + Opus 5 两套完整 Agent 系统。它们的默认提示词、上下文管理和工具调度方式并不相同。

其次，Claude 的生成侧输出量约为 Codex 的 16 倍。它确实进行了远多于对手的推理，不能把计算预算差异完全归因于模型能力。

镜像第一场还出现过一次明显的工具调用异常：Codex 在两个首报价状态把最低合法数量 2 写成 1，并高速重复提交。所有非法动作都被引擎拒绝，没有改变牌局，但它污染了该场的延迟和上下文，因此这不是一组毫无瑕疵的模型对照。

所以，这些结果不足以证明“Claude 在所有游戏中都比 GPT 更强”。它能证明的是：在这套持续 session 的大话骰 Agent 系统里，Claude 展示了更稳定的条件推理、对手建模和主动诱导能力。

## 从计算器变成玩家

我们通常用题目评测模型：给定所有条件，能否得到正确答案。

但在游戏里，对手不是题目的一部分。对手会观察你、选择动作、隐藏信息，也会故意改变你接下来需要解决的问题。

Codex 更多是在计算“这口价有多大概率成立”。Claude 则开始追问：“它为什么偏偏选择了这口价？如果它会这样反应，我应该给它看到什么？”

从前一个问题走到后一个问题，可能正是 LLM 从计算器变成玩家的那一步。

而这场比赛最精彩的一幕，并不是 Claude 说出了一句漂亮的假话。

是它连续说了几次真话，而对手始终不信。
