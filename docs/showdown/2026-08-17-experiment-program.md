# Liar's Dice Agent Showdown：补充实验计划

日期：2026-08-17

## 研究问题

这组实验不试图仅凭几局比赛宣布“哪个模型更强”，而是逐步拆开四个变量：

1. **模型**：`gpt-5.6-sol` 与 Claude Opus 5。
2. **座位与随机局面**：A/B 座位、先手、私有骰子。
3. **会话记忆**：BO3 是否复用同一模型 session。
4. **通信协议**：自然语言发言是否参与对手建模。

所有对局均由同一个权威引擎裁决；模型只能通过各自座位的 MCP 读取可见状态和提交动作，不能读取对方私有骰子或思考。

## 固定指标

每个实验至少保存：

- 完整 `run.json`、双方 JSONL 与 stderr；
- 模型实际标识、种子、座位、先手规则、session 规则；
- 系列比分、每局轮数、每座位 bid/challenge 次数；
- challenge 命中率、非法/过期动作数；
- 跨局显式引用（启发式指标，不能等同于真实记忆）；
- token、缓存与费用（仅在运行器真实返回时记录）；
- 每局确定性 replay 校验与归档文件哈希。

## 判读规则

- **重复实验**回答“原现象是否容易再次出现”，不能单独排除座位偏差。
- **镜像实验**和 E0 成对解读；同种子换边后，私有信息跟着座位而不是模型走。
- BO3 的两三局并非独立样本；复用 session 正是被测机制，同时也降低了统计独立性。
- 胜负、策略质量与资源效率分开报告。模型使用更多计算赢下比赛，不等于在等成本条件下更强。
- 自然语言只能证明日志中出现了某种陈述，不能直接证明未展示的内部思考。

## 成本与运行纪律

- 同一时间只运行一场包含 Opus 的真实比赛，避免并发限流或缓存竞争污染延迟与成本数据。
- 每完成一个实验先做机械统计、replay 和哈希归档，再启动下一项。
- 第一批 E1+E2 完成后设置检查点：根据新增信息决定是否值得继续 E3–E5。
