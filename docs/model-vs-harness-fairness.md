# 你测到的是模型，还是 Harness？

### 如果早一天发稿，我会给 DeepSeek 写上一种并不存在的性格

> 本文由 AI 协助整理。案例与数据来自《开！》AI Arena 的真实跑批。文中结论只适用于当时的游戏规则、模型版本与实验设置，不作通用能力排名。

---

[DEV Community 上的一篇文章](https://dev.to/haoxiangli/are-you-benchmarking-the-model-or-the-harness-2bke)提出了一个很尖锐的问题：*Are You Benchmarking the Model—or the Harness?* 把它放进中文语境，最值得讨论的是一个数字：40% 修完只剩 6%。下面用一次 AI 大话骰实验，拆开这个问题。

如果我早一天把稿子发出去，DeepSeek V4-Pro 可能已经多了一种性格：**不看骰也敢报价。**

先简单介绍一下这张桌子。大话骰里，每个人面前都有一组暗骰，玩家轮流声称“全桌至少有 N 个某点数”，下一位只能继续加码，或者开牌质疑。所有人摊开骰子后，报价成立则报价者赢，数量不够则质疑者赢。《开！》还把“看自己的骰子”做成一个明确动作，因此玩家也可以不看就报；这种报价在文中称为“蒙报”。

证据看起来很充分。第一批 AI 大话骰比赛跑完，它有将近四成报价发生在看骰之前。

这很容易写成一个故事。它更敢赌，更相信直觉，或者喜欢先声夺人；另一个模型总要先看骰、再计算，风格显得谨慎。胜率、台词和动作记录摆在一起，两种“性格”已经呼之欲出。

但我检查上下文时发现，即使模型没有使用计算动作，系统仍然会把粗略概率写进提示词，候选动作还按照概率排好了顺序。它表面上盖着骰盅，实际上已经收到场外提示。

修复后，V4-Pro 的蒙报率从约 **40% 降到约 6%**。

那段很像模型洞察的分析，只是在解释一个程序问题。一个足够吸引人的结论，就这样从数据里消失了。

随后，我又找到了三个同类 bug。首批约 60 场比赛里，最显眼的模型差异在修复后收拢了大半。这件事改变了我对模型评测的理解：**Arena 直接测到的是模型与 Harness 共同组成的系统。想把结果归因给模型，得先证明测量它的那套系统没有偷偷替它思考、遮住它的输入，或者改写它的失败。**

这里的 Harness，是包在模型外面的整套运行框架：提示词、上下文拼装、工具、动作空间、token 预算、供应商路由、输出解析、重试和降级。模型负责作答，但它看到什么、能做什么，以及什么答案最后会被记进数据库，都由 Harness 决定。

## 40% 的“性格”，修完只剩 6%

最初我以为这只是一处实现疏忽。继续往下查，第二个、第三个、第四个问题相继出现。更麻烦的是，它们都没有让比赛停下来。每场对局仍然有动作、有台词、有比分，数据看起来甚至很完整。

| Harness 问题 | 当时看见的“模型特点” | 修复以后 |
|---|---|---|
| `max_tokens=400` 截断长输出 | 格式差，经常需要 bot 顶班 | 格式失败和顶班明显下降 |
| 未计算也提供粗略概率，候选动作按概率排序 | 喜欢不看骰就报价 | 蒙报率约 40% → 约 6% |
| 没有转发对手台词 | 不会读人，棋力也弱 | 恢复台词后，胜率回到约 40%–60% |
| 主观判断只保存前 100 字 | 思路跳跃，留档混乱 | 保存全文后，原有判断链重新出现 |

它们分别干扰了评测的四个环节。

概率泄漏改变了模型的输入；漏转台词拿走了它本该拥有的信息；token 上限截断了它的输出；数据库又改变了我们事后用来解释行为的证据。Harness 先影响模型怎么下，再影响我怎么看。

更危险的是，这些偏差会自动长出合理解释。长输出被截断，可以归因于指令遵循差；读不到对手台词，可以归因于社交推理弱；候选动作已经替它排好，结果却会被当作决策能力。只要最终分数还能生成，人很容易跳过测量过程，直接给模型贴标签。

这带来一个不太舒服的结论：评测框架同样在场上。

所以我现在看到一张模型榜单，先不问谁赢了。我先问：**这场比赛究竟给每个模型出了什么题？**

## 同一份 Prompt，为什么仍是两道题？

模型竞技场经常用“所有模型使用同一份 Prompt”来证明公平。它当然必要，但远远不够。

在《开！》的早期版本里，两边拿到的 system prompt 逐字相同。与此同时，下面任何一项都足以改变实际任务：

- 动作候选按照什么顺序出现；
- 系统是否附送了模型没有主动查询的信息；
- 对手说过的话有没有完整进入上下文；
- 推理 token 和最终回答是否共用预算；
- 输出被截断以后，是判失败、重试，还是让 bot 接管；
- 型号字符串最终被路由到哪个供应商和量化版本；
- 解析器保存原始回答，还是只截取其中一段。

Prompt 只是模型收到的字符串。模型实际面对的题目，还包括信息边界、工具权限、计算资源和失败规则。

这也解释了为什么统一设置有时会产生系统性的偏向。短回答模型容易躲过截断，长推理模型可能在输出正文前耗完预算；倾向选择靠前选项的模型会受到候选顺序影响；依赖对话线索的模型，在漏转台词时损失更大。表面上一视同仁的 Harness，对不同模型未必产生相同影响。

控制条件越整齐，实验就越公平吗？未必。答案取决于我们究竟想测什么。

## “公平”没有统一答案

后来我发现，很多关于“公平”的争论，其实在回答不同问题。

如果产品已经有一套固定接口，我想知道换成哪个模型最省事，那就应该固定 Prompt、工具、预算和解析规则。这测的是模型对共同产品契约的适配程度。

如果我想知道每个模型能达到的上限，就应该分别优化提示词、工具和推理设置。此时结果包含了适配工作，不能再说它们是在同一条件下裸跑。

如果我要比较投入产出，则要固定成本、延迟或 token 消耗。这个实验回答的是同一资源约束下谁更有效，而非谁的绝对能力更强。

三种口径都合理：

| 口径 | 控制方式 | 能回答的问题 |
|---|---|---|
| 接口公平 | 使用相同 Prompt、工具、预算和动作空间 | 谁更适合接入同一套产品 |
| 能力上限 | 针对每个模型分别调优 | 每个模型经过适配后能做到什么 |
| 资源公平 | 固定费用、延迟或 token | 同等投入下谁的产出更高 |

麻烦通常出在结论越过了实验口径。统一 Prompt 的比赛可以说明“谁更适应这份 Prompt”，却不能直接宣称模型能力上限；分别调优后的成绩可以展示上限，但调优者的经验也进入了结果。评测报告必须先声明自己采用哪种公平，再限定它能支持什么结论。

《开！》当前的素颜赛道选择了第一种。它主要回答一个产品问题：在同一套游戏接口里更换模型，玩家会得到怎样的对手？

口径选定后，麻烦才刚开始。接下来要防止 Harness 再次伪装成模型能力。

## 怎样防止 Harness 再次混进成绩

确定问题后，公平评测才变成一组可执行的约束。

首先，每个模型只能通过普通玩家接口行动。它只能看到自己的骰子和公开事件，所有动作由同一个确定性引擎验证。信息边界写进 schema，不能只靠提示词提醒。

其次，同一副骰要连续打两次，交换双方座位。这样可以抵消部分先手、座位和随机牌面的影响。单场胜负不进入型号结论。

第三，冻结的不只是一段 Prompt。候选顺序、上下文序列化、工具返回、采样参数、解析器和代码版本都属于实验条件。每个批次保存 Prompt 哈希和 git commit；其中一项改变，就另开批次。

第四，记录服务端实际执行的配置。请求里写了 `max_tokens` 或推理开关，不代表供应商一定照做。每次调用都要保存 completion token、reasoning token、finish reason、延迟、费用和实际路由。空回复与超时也必须留在样本里。

最后，让重试、修复和 bot 顶班出现在成绩旁边。线上产品需要兜底，但评测不能让兜底悄悄冒充模型行为。榜单同时报告格式失败、拒绝和顶班率，并单独计算零顶班样本。

这些规则听起来像工程卫生，却直接决定结论能不能成立。一套可靠的产品 Harness 会尽量掩盖失败，让用户继续玩；一套可信的评测 Harness 必须把失败暴露出来。两者可以使用同一套代码，但数据口径不能混在一起。

即使做完这些，榜单仍然有边界。控制变量只能让答案更可靠，不能替实验回答它没有问过的问题。

## 一张榜单，最多能说到哪里？

我把《开！》里的指标分成三层。

- **合规**：非法动作、格式失败、拒绝和降级顶班，说明模型能否履行当前接口契约。
- **棋力**：胜率、开牌命中和净筹码，说明它在当前规则与信息条件下的决策质量。
- **风味**：虚报、蒙报、抬价深度、台词和反应节奏，说明更换模型后，玩家能否感到稳定的行为差异。

这三层都值得测，但解释范围不同。格式成功可能来自模型的指令遵循，也可能来自宽松的解析器；胜率说明它会不会玩这套游戏，不能直接外推成通用推理排名；风味则更接近产品体验，样本少时只能描述现象，不能写成持久人格。

当前干净集包含 7 个型号、11 组对手关系、22 个座位臂和 44 场比赛。它足以暴露明显的 Harness 问题，远不足以给模型做通用排名。记忆赛道还会带来跨场路径依赖，因此与无记忆的素颜赛道分开保存，不共用一张榜。

我现在愿意从这些数据里说的，只有很窄的一句话：**在已记录的版本、路由、预算、规则和样本中，不同模型作为《开！》的对手，表现出了哪些差异。**

再往外一步，都需要新的实验。

## 每个模型结论，都该经得起一次反事实

最初那个“DeepSeek 喜欢蒙着骰盅报价”的故事很好写。它有数字，有反差，也符合人们对模型性格的兴趣。唯一的问题是，它不是真的。

40% 变成 6%，没有模型升级，也没有 Prompt 调优。我只是拿掉了 Harness 偷偷提供的信息。

这正是模型评测最容易忽略的部分。排行榜把模型放在聚光灯下，测量工具因此退到了黑暗里；可工具怎样组织输入、分配预算、处理错误和保存答案，始终参与着最终得分。

完全中性的 Harness 很难存在。动作空间怎样设计、预算给多少、哪些指标值得统计，本身都有取舍。但我们至少可以让这些取舍可见：固定版本，保存原始调用，公开失败率，区分降级样本，说明结论适用的边界。

现在，每当我准备写下一句“这个模型更勇敢”或者“那个模型不擅长读人”，都会先问一个反事实问题：**只改变 Harness，这个差异还会存在吗？**

如果没有做过这个检查，所谓模型特点，暂时只能算一个待排查的现象。

所以，下次再看到一个模型表现得勇敢、谨慎、聪明或者笨拙，我会先忍住解释它的性格。
