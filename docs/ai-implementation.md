## 1. 概率表盘怎么算

### 1.1 函数

```
probBidTrue(bid, myDice, oppCount, zhai) → [0, 1]
```

回答一个问题：**"桌上至少有 count 个 face"这句话为真的概率**——从"我"的视角。

### 1.2 数学

三步：

1. **已见匹配数**：在自己骰面里数 `face`（飞局把 1 也算上）。
   `mine = countBid(bid, myDice, zhai)`
2. **还缺几个**：`need = bid.count − mine`。`need ≤ 0` 直接返回 1（这话已然为真）；`need > 对方骰数` 返回 0（物理不可能）。
3. **对方未知骰补齐的概率**：对方 `oppCount` 颗骰视为均匀随机，每颗命中概率
   - 飞局且报点 ≠ 1：`p = 2/6`（本点 + 癞子 1）
   - 斋局，或报点 = 1：`p = 1/6`

   则 `P = P(X ≥ need)`，`X ~ Binomial(oppCount, p)`，二项分布尾部精确求和（无近似、无采样）。

例：我 5 骰 `[3,3,4,4,6]`，对方报「3 个 4」（飞局）。已见 4,4 共 2 个，缺 1；对方 5 颗每颗 1/3 命中，`P(X≥1) = 1 − (2/3)⁵ ≈ 87%`。

### 1.3 视角与两个前提假设（重要）

**是的，纯单方视角**，且带一个明确的行为假设：

| 前提 | 含义 |
|---|---|
| **信息 = 自己骰面 + 对方骰子数量** | 不含对方任何私有信息。架构上也拿不到：`observe()` 返回的 schema 里根本没有对方骰面字段（§4）。 |
| **对方骰面 = 均匀随机**（"乱报假设"） | 不利用对方的报数历史做贝叶斯更新。对方报「3 个 4」这件事本身其实是证据（诚实玩家报 4 说明他手里多半有 4），表盘刻意不用这个证据。 |

第二条是**设计决定而非缺陷**（附 B.1 原文）：*"表盘是地板不是答案：它假设对面乱报，而游戏建立在对面不乱报上——AI 可以剥削'表盘奴隶'（贴着你的开牌阈值上方虚报），你的计算器会成为它的鱼饵。"* 读心的空间就在真实概率与表盘数字的差值里。

### 1.4 双发（附 B.1 红线）

同一个函数四处使用，任何一方拿到的事实另一方都有等价物：

| 使用方 | 位置 | 呈现 |
|---|---|---|
| 玩家 | 表盘 `#gauge` | "按你的骰子算，「3 个 4」为真 87%" |
| 玩家 | 报数按钮 | "报 2 个 4 · 100%"（自己候选报价的为真概率） |
| 老李头（LLM） | prompt 注入 | 当前报价 P + 抬价候选前 6 的 P（见 §2.3） |
| 沉默模式 bot | 决策 | 开牌阈值 + 选 P 最高的抬价（见 §2.6） |

## 2. AI 提示词管线

### 2.1 调用预算与形态

DESIGN §3.1 限定**每手 1 次调用 + 结算 1 次**（成本 <0.5 元/场）。因此没有做多轮 function calling —— 工具结果**预先算好、注入 prompt**（等价于"老周每手都用计算器"，符合附 B.1"事实工具可有"；预注入的全部是事实，没有任何"该怎么做"的建议，策略红线未破）。

### 2.2 SYSTEM（由人设五件套拼装，Q10）

人设是一等公民对象（`personas.js`：身份/嘴臭度/策略倾向/回复风格/装备），SYSTEM 全部从对象拼出：

```
你是{name}，{identity}正和客人玩大话骰。{TONES[tone]}{style}你收到的全是真实数据，禁止编造数字。
{flaws ——Q11 性格缺陷：要面子（嘴棋耦合）/记仇/自负，可被玩家读出利用}
规则提要：（同前）
严格输出一行 JSON：{"action":…,"say":"台词","note":"决策理由"}
```

当前唯一人设：**老李头**（tone=hell 地狱档拉满；策略与装备继承原设定：每手必算、稳健记仇、不用盲）。嘴臭度绑定人设、无玩家设置项；Q6 内容边界（只锚定真实数据、只毒打法、不碰人身、不用脏话）为全人设不变量。

### 2.3 USER（每手动态拼装，五段事实）

`buildPrompts(ob, profile)` 按固定顺序拼五段，**全部来自引擎 observe() 与本地档案，无一编造**：

| 段 | 内容 | 来源 |
|---|---|---|
| ① 局面 | 第几局、自己骰面、对方骰数、池深、斋标记 | `ob.yourDice / diceCount / potUnits / zhai` |
| ② 本局进程 | 看骰/报数/宣言的时序叙事，**带用时**（"用时7.4秒"） | 公开事件流 `narrate()`；对方揭盅时机也在内（§2.3 裁决） |
| ③ 当前报价 | 报价内容 + **为真概率**（按他的骰面算，§1 同一函数） | `probBidTrue` |
| ④ 可选动作 | 开牌；抬价候选=全部合法报价中 **P 最高的 6 个**（各带 P），并注明"也可报其他合法阶梯"；可用宣言 | `allLegalBids` × `probBidTrue` |
| ⑤ 档案 | 跨场摘要（场次胜负、上场虚报率/开牌命中/平均思考）+ 他的旧笔记末 5 条 | localStorage `profileBrief()`，与玩家在"它眼中的你"页看到的是**同一份**（§5.1 明牌） |

### 2.4 真实样例（seed 20260807 实际生成）

玩家先看骰、想了 7.4 秒报「3 个 4」，轮到老周：

```
第 1 局。你 5 颗骰：[3, 3, 4, 4, 6]，对方 5 颗暗骰。池 2 注。
本局进程：对方掀盅看了骰；对方报 3 个 4（用时7.4秒）。
当前报价：对方报「3 个 4」。按你的骰子算，此话为真的概率 87%。
可选动作：开牌；抬价（高可信候选：3个6=54%，4个3=54%，4个4=54%，3个5=21%，
4个6=21%，5个3=21%；也可报其他合法阶梯）。
你对这位客人的档案笔记：交手3场，客人赢1场。上一场客人虚报率40%，开牌2次命中1次，
平均思考6.2秒。你的旧笔记：他抬价到4个就手抖；秒点的都是真话
```

### 2.5 输出解析与降级链

`parseDecision(text, ob)`：

1. 从回复中提取首个 `{...}` 块，`JSON.parse`；
2. **合法性校验**：动作类型必须在 `ob.legal` 集内；bid 还要过 `isLegalBid` 阶梯校验（数量/点数/上限）；
3. `say` 截 60 字、`note` 截 120 字；
4. 任何一步失败 → 返回 `null` → **降级沉默模式**（SilentBot 顶班落子，无台词），事件记 `silentFallback: true`。

LLM 网络层（`llm.js`）：BYOK 双格式（OpenAI 兼容 / Anthropic），浏览器直连、key 只存 localStorage、10s 超时。降级链：自带 API → 沉默模式（官方限额通道暂未建，§3.4 的中间层）。

**决策日志**（附 B.3）：每手记 `{round, facts(注入的全文), raw(LLM 原始回复), action, say, note, silentFallback}`——这是"台词不许编"的审计落点，note 结算后进档案。

### 2.6 结算判词（第二类调用）与沉默模式

- `settleVerdict(channel, {won, statsText})`：场终 1 次调用。SYSTEM 复用人设（去掉动作 JSON 约束，换成判词约束），USER = 本场统计文本（局数胜负、虚报率、开牌命中、被开、最久一手想了几秒报了什么）。输出 `{verdict(给客人的判词), note(记档案)}`，失败降级模板判词——模板同样只用真实统计填充。
- **沉默模式**（`silent.js`）：无 LLM 时的纯数学行棋。规则仅两条：对方报价 `P < 0.25` 或无价可抬 → 开牌；否则报**自己视角 P 最高**的合法抬价。不宣言、不说话。0.25 是行为参数（§3.2），不是失误注入。

### 2.7 公平性小结

- 他**拿不到**你的骰面——不是承诺，是 `observe()` schema 里没有这个字段；
- 他算概率用的函数和你表盘上的**同一个**；
- prompt 里没有任何策略建议（没有"建议开牌"、没有最优动作表），只有世界的事实——他怎么打，是模型自己的事。
